# 客户管理库操作手册

> 给第一次接触本系统的人看的说明。  
> 读完这份手册，你应该能明白：这是什么、怎么安装、怎么初始化客户库、怎么让 Claude Code / Agent 帮你自动管理客户信息。

---

## 1. 这是什么

客户管理库是一套基于 Markdown 和 Agent 的客户信息管理系统。

它不是传统 CRM，也不是简单表格，而是一个“客户长期服务大脑”。

它帮助你把这些零散信息：

- 微信聊天
- 录音转写
- 面谈记录
- 客户口述
- 保单资料
- 健康告知信息
- 方案沟通
- 跟进记录
- 团队协作反馈

整理成这些长期可用资产：

- 客户主档案
- 客户事件流
- 客户分析 brief
- 专属解决方案
- 跟进清单
- 团队协同任务
- 服务复盘
- 数据质量报告

一句话：

> 它让 Agent 帮你持续理解客户、服务客户、跟进客户，而不是只记录客户。

---

## 2. 它适合谁

适合：

- 保险代理人
- 理赔/保单整理服务者
- 咨询顾问
- 私域运营者
- 知识服务/AI 服务从业者
- 需要团队协同处理客户信息的人

不适合：

- 只想要一个简单通讯录的人
- 不愿意做任何结构化记录的人
- 希望系统自动替代专业判断的人

---

## 3. 基本概念

## 3.1 Skill 仓库

就是当前这个仓库。

它保存：

- Agent 使用规则
- 操作手册
- 数据模型
- 入库流程
- 入口评分标准
- 团队协同规则
- 脚本工具

它不保存真实客户数据。

## 3.2 私有客户库

这是你真正保存客户资料的地方。

例如：

```text
D:\Claude\客户解决方案库-私有
```

里面会保存：

- 客户档案
- 客户事件流
- 业务模块
- 方案与分析
- 跟进记录
- 团队协同任务

## 3.3 Agent

Agent 指 Claude Code、Codex 或其他能读取文件、执行规则、调用脚本的 AI 助手。

它负责：

- 判断信息是否值得入库
- 匹配客户
- 创建/更新档案
- 写事件记录
- 生成分析和方案
- 刷新索引
- 做数据质量检查

## 5. 安装方式

你可以选择三种安装方式。

## 5.1 安装为个人 Skill

适合你希望所有 Agent 都能调用它。

### Windows

```powershell
mkdir $env:USERPROFILE\.codex\skills -Force
git clone https://github.com/wytnzs/customer-solution-library.git $env:USERPROFILE\.codex\skills\customer-solution-library
```

安装后，重启或新开一个 Agent 会话，然后说：

```text
使用 $customer-solution-library，帮我管理客户库。
```

### macOS / Linux

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/wytnzs/customer-solution-library.git ~/.codex/skills/customer-solution-library
```

## 5.2 安装为项目 Skill

适合你只想在某个项目里使用。

进入你的项目目录：

```powershell
cd D:\Claude\某个项目
```

安装：

```powershell
git clone https://github.com/wytnzs/customer-solution-library.git .claude\skills\customer-solution-library
```

然后对 Claude Code 说：

```text
使用 .claude/skills/customer-solution-library 这个 Skill，帮我初始化客户库。
```

## 5.3 作为独立工具使用

适合只想使用脚本，不安装到 Agent。

```powershell
git clone https://github.com/wytnzs/customer-solution-library.git D:\Claude\customer-solution-library
cd D:\Claude\customer-solution-library
```

测试：

```powershell
python scripts/customer_library.py score-intake --text "张先生说孩子刚上小学，最近体检发现甲状腺结节，想看看重疾险，周五晚上有空。"
```

如果输出类似：

```json
{
  "signal_score": 76,
  "signal_level": "S",
  "route": "immediate_process"
}
```

说明安装成功。

## 6. 第一次使用：初始化客户库

进入 Skill 仓库：

```powershell
cd D:\Claude\customer-solution-library
```

初始化一个私有客户库：

```powershell
python scripts/customer_library.py init --base D:\Claude\客户解决方案库-私有
```

初始化后会得到：

```text
客户解决方案库-私有/
  00-入口池/
  01-客户档案/
  02-客户事件流/
  03-业务模块/
  04-方案与分析/
  05-团队协同/
  06-服务跟进/
  07-客户分层/
  08-复盘案例/
  90-索引与看板/
  99-模板与规则/
```

这个目录才是真实客户资料存放处。

## 7. 推荐给 Agent 的启动说明

第一次让 Agent 接手客户库时，可以直接复制下面这段：

```text
你现在使用 customer-solution-library Skill。

客户库路径是：
D:\Claude\客户解决方案库-私有

请遵守以下规则：
1. 所有新客户信息先进入入口判断，不要直接写入主档案。
2. 先判断信息价值，再决定是否入档。
3. 同名客户不能自动并档。
4. 主档案只写稳定摘要，历史细节写入客户事件流。
5. 不确定的信息标记为待确认。
6. 涉及健康、理赔、保单、投诉、承诺、隐私的信息要保守处理。
7. 每次更新后刷新索引。
```

## 8. 一步操作

一步操作就是：你只说一句话，Agent 自动完成后续动作。

适合：

- 录入客户
- 摘录聊天记录
- 查询客户
- 生成分析
- 设置跟进
- 做质检

## 8.1 一步录入客户

你说：

```text
录入客户：张先生，杭州，李姐转介绍，已婚一孩，想了解重疾险，最近体检发现甲状腺结节，周五晚上有空。
```

Agent 应自动完成：

1. 判断这条信息价值。
2. 搜索是否已有张先生。
3. 判断是否存在同名风险。
4. 若不能确认，放入待匹配。
5. 若能确认，创建或更新客户档案。
6. 写入客户事件流。
7. 更新保险业务模块。
8. 设置下一步动作。
9. 刷新客户索引。
10. 汇报处理结果。

## 8.2 一步整理聊天记录

你说：

```text
整理这段聊天记录并入库：
<聊天内容>
```

Agent 应输出：

```markdown
## 对话摘录

- 客户明确事实：
- 客户原话：
- 显性需求：
- 隐性顾虑：
- 待确认信息：
- 建议更新：
- 下一步动作：
```

## 8.3 一步查询客户

你说：

```text
查一下客户：张先生
```

Agent 应先搜索候选客户。

如果有多个张先生，必须列候选：

```markdown
找到多个可能客户：

1. CUST-0001｜杭州三口之家｜保险客户
2. CUST-0003｜上海张先生｜合作线索

仅凭姓名不能安全判断，请确认是哪一位。
```

## 8.4 一步生成客户分析

你说：

```text
分析客户：CUST-0001
```

Agent 应读取：

- 客户主档案
- 最近事件流
- 相关业务模块

并输出：

```markdown
# 客户分析 Brief

## 结论先行
## 已知事实
## 推断判断
## 待确认信息
## 风险/机会排序
## 下一步建议
```

## 8.5 一步数据质量检查

你说：

```text
检查客户库健康状态。
```

Agent 应运行：

```powershell
python scripts/customer_library.py audit --base D:\Claude\客户解决方案库-私有
```

并汇报：

- 缺少下一步动作的客户
- 缺少跟进日期的客户
- 信息完整度偏低的客户
- 待处理入口
- 待匹配入口
- 疑似重复客户
- 隐私风险
- 待复核协同任务

## 9. 三步操作

三步操作适合高价值、高风险、不确定的客户信息。

标准三步：

```text
第一步：判断价值
第二步：匹配客户
第三步：正式入档
```

## 9.1 第一步：判断价值

你说：

```text
先只判断这段客户信息的价值，不要入库：
<客户信息>
```

Agent 输出：

```markdown
## 信号评分

- 身份识别：
- 业务相关：
- 决策/行动：
- 风险/责任：
- 长期资产：
- 扣分项：
- 总分：
- 等级：
- 建议路由：
```

## 9.2 第二步：匹配客户

你说：

```text
根据上面的信息，帮我匹配可能客户，但先不要写入。
```

Agent 输出：

```markdown
## 客户匹配

| 候选客户 | 匹配依据 | 冲突点 | 建议 |
```

## 9.3 第三步：正式入档

你说：

```text
确认是 CUST-0001，请正式入库。
```

Agent 执行：

- 写入事件流
- 更新主档案摘要
- 更新业务模块
- 设置下一步动作
- 刷新索引

## 10. Agent 分工

如果你想让多个 Agent 分工，可以按下面拆。

## 10.1 Intake Agent

入口判断 Agent。

负责：

- 接收原始信息
- 判断来源类型
- 打信号分
- 决定路由

指令：

```text
作为 Intake Agent，处理这条客户信息：<内容>
```

## 10.2 Identity Agent

身份匹配 Agent。

负责：

- 提取身份锚点
- 搜索已有客户
- 识别同名风险
- 阻止误并档

指令：

```text
作为 Identity Agent，判断这条信息属于哪个客户：<内容>
```

## 10.3 Profile Agent

档案更新 Agent。

负责：

- 创建客户主档案
- 更新稳定摘要
- 写变更记录
- 刷新索引

指令：

```text
作为 Profile Agent，把这条已确认信息更新到 CUST-0001。
```

## 10.4 Event Agent

事件流 Agent。

负责：

- 记录每次沟通
- 保存来源、时间、转写质量、参与人
- 不直接写最终结论

指令：

```text
作为 Event Agent，把这段沟通写入客户事件流：<内容>
```

## 10.5 Analysis Agent

客户分析 Agent。

负责：

- 读取档案和事件流
- 区分事实、推断、待确认
- 生成客户分析 brief

指令：

```text
作为 Analysis Agent，分析客户 CUST-0001。
```

## 10.6 Solution Agent

方案 Agent。

负责：

- 生成专属方案草稿
- 标注方案边界
- 区分内部版和客户可读版

指令：

```text
作为 Solution Agent，为客户 CUST-0001 生成专属方案草稿。
```

## 10.7 Follow-up Agent

跟进 Agent。

负责：

- 维护下一步动作
- 维护跟进日期
- 生成跟进清单

指令：

```text
作为 Follow-up Agent，生成本周客户跟进清单。
```

## 10.8 Collaboration Agent

协同 Agent。

负责：

- 生成团队协同摘要
- 分派任务
- 标注复核要求
- 控制脱敏和权限

指令：

```text
作为 Collaboration Agent，为客户 CUST-0001 生成团队协同任务。
```

## 10.9 Audit Agent

质检 Agent。

负责：

- 检查客户库健康状态
- 找重复客户
- 找隐私风险
- 找缺跟进和待复核任务

指令：

```text
作为 Audit Agent，检查客户库健康状态。
```

## 11. 信息价值评分

客户信息进入系统后，先打分。

总分 100 分：

| 维度 | 分值 |
|---|---:|
| 身份识别价值 | 15 |
| 业务相关价值 | 20 |
| 决策/行动价值 | 25 |
| 风险/责任价值 | 25 |
| 长期资产价值 | 15 |

等级：

| 分数 | 等级 | 处理 |
|---:|---|---|
| 75-100 | S | 立即处理 |
| 55-74 | A | 待处理 |
| 35-54 | B | 轻记录 |
| 15-34 | C | 低价值归档 |
| 0-14 | D | 可丢弃 |

以下情况至少按 A 级处理：

- 客户约时间
- 客户补资料
- 健康异常
- 既往症
- 理赔/拒赔
- 投诉/纠纷
- 保单缴费/续保/退保
- 明确承诺
- 身份证/银行卡/手机号/病历
- 转介绍
- 强烈购买意愿或强烈负面情绪

## 12. 隐私与安全

不要把真实客户敏感信息提交到 GitHub。

不要明文保存：

- 完整姓名
- 手机号
- 身份证号
- 银行卡号
- 完整保单号
- 病历原件
- 体检报告原件

建议：

- 用 `CUST-0001` 这类编号管理客户。
- 文件名使用别名，不写完整真实身份。
- 高敏资料单独加密保存。
- 给团队协同时只提供最小必要信息。
- 给客户看的内容和内部判断分开。

## 13. 常见问题

## 13.1 可以直接上传录音吗？

本系统主要处理文字。建议先把录音转成文字，再交给 Agent 摘录。

## 13.2 只有口述，没有聊天原文，可以入库吗？

可以，但应标记为 `manual_summary`，可信度低于原始聊天记录。

## 13.3 同名客户可以自动合并吗？

不可以。

只有姓名相同，不能并档。必须至少有来源、城市、手机号后四位、历史事件、业务线等辅助锚点。

## 13.4 真实客户库要不要放进这个仓库？

不要。

这个仓库只放 Skill 和工具。真实客户库应单独保存，并加入 `.gitignore`。

## 14. 最推荐的日常节奏

每天：

```text
处理入口池
→ 高价值信息入档
→ 设置下一步跟进
```

每周：

```text
刷新索引
→ 检查待匹配
→ 生成跟进清单
→ 处理待复核任务
```

每月：

```text
生成数据质量报告
→ 清理低价值归档
→ 检查疑似重复客户
→ 复盘高价值客户案例
```

---

## 15. 一句话记住

> 先入入口池，先判断价值，先匹配身份，再更新客户。

这是整个客户管理库最重要的原则。
