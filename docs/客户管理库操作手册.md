# 客户管理库操作手册

> 面向使用者和 Agent 的操作说明。  
> 这份手册只回答五个问题：这个仓库有什么、能做什么、最小计量单位是什么、为什么比传统方案好、如何一条指令安装。

---

## 1. 仓库包含的内容及用途

这个仓库是一套客户管理 Skill，不保存真实客户资料。

它的作用是：让 Claude Code、Codex 或其他 Agent 按统一规则帮你管理客户信息。

仓库内容如下：

```text
customer-solution-library/
  SKILL.md
  agents/
    openai.yaml
  docs/
    客户管理库操作手册.md
  references/
    conversation-ingestion.md
    data-model.md
    data-quality-audit.md
    intake-routing.md
    output-formats.md
    team-collaboration.md
    workflows.md
  scripts/
    customer_library.py
```

各部分用途：

| 内容 | 用途 |
|---|---|
| `SKILL.md` | Skill 主规则。告诉 Agent 什么时候使用本 Skill，以及处理客户信息时遵守什么原则。 |
| `agents/openai.yaml` | Skill 在 Agent 界面里的显示名称、简介和默认提示。 |
| `docs/客户管理库操作手册.md` | 给使用者看的操作说明，也就是本文档。 |
| `references/data-model.md` | 客户库目录结构、客户档案字段、生命周期、客户类型、事件流规则。 |
| `references/intake-routing.md` | 信息入口评分规则。用于判断一条客户信息是否值得入库。 |
| `references/conversation-ingestion.md` | 聊天记录、录音转写、口述记录如何摘录并进入客户库。 |
| `references/output-formats.md` | 客户速览、客户分析、方案、跟进建议等输出格式。 |
| `references/team-collaboration.md` | 团队协同、分享、脱敏、复核和交接规则。 |
| `references/data-quality-audit.md` | 数据质量检查规则，包括重复客户、缺跟进、隐私风险等。 |
| `references/workflows.md` | 客户录入、查询、分析、方案、跟进、复盘的标准流程。 |
| `scripts/customer_library.py` | 可执行工具。用于初始化客户库、刷新索引、搜索客户、入口评分、生成质检报告。 |

需要区分两个概念：

```text
本仓库 = 客户管理规则和工具
私有客户库 = 真实客户资料存放处
```

真实客户资料不应该放进本仓库。

## 2. 具体功能及使用方法

### 2.1 初始化客户库

功能：创建一个私有客户库目录。

命令：

```powershell
python scripts/customer_library.py init --base D:\Claude\客户解决方案库-私有
```

初始化后会生成：

```text
客户解决方案库-私有/
  00-入口池/
  01-客户档案/
  02-客户事件流/
  03-业务模块/
  04-方案与分析/
  05-团队协同/
  06-服务跟进/
  07-客户分层/
  08-复盘案例/
  90-索引与看板/
  99-模板与规则/
```

用途：

- 第一次使用时运行。
- 一个客户库只需要初始化一次。

### 2.2 判断客户信息是否值得入库

功能：对一段客户信息打分，判断处理优先级。

命令：

```powershell
python scripts/customer_library.py score-intake --text "张先生说孩子刚上小学，最近体检发现甲状腺结节，想看看重疾险，周五晚上有空。"
```

输出示例：

```json
{
  "signal_score": 76,
  "signal_level": "S",
  "route": "immediate_process"
}
```

含义：

| 字段 | 含义 |
|---|---|
| `signal_score` | 信息价值分数，满分 100 |
| `signal_level` | 信息等级：S/A/B/C/D |
| `route` | 建议处理方式 |

等级说明：

| 等级 | 处理方式 |
|---|---|
| S | 立即处理，应该匹配客户并入库 |
| A | 待处理，应该整理摘要并跟进 |
| B | 轻记录，不一定更新主档案 |
| C | 低价值归档 |
| D | 可忽略或丢弃 |

### 2.3 搜索客户

功能：根据客户编号、姓名、别名、关键词搜索客户。

命令：

```powershell
python scripts/customer_library.py find --base D:\Claude\客户解决方案库-私有 --query 张先生
```

用途：

- 查询客户是否已存在。
- 识别同名客户。
- 录入新信息前先匹配客户。

注意：

只有姓名相同，不能自动并档。必须结合来源、城市、手机号后四位、历史事件、业务线等身份锚点。

### 2.4 刷新客户索引

功能：根据客户档案自动生成客户总索引。

命令：

```powershell
python scripts/customer_library.py index --base D:\Claude\客户解决方案库-私有
```

生成文件：

```text
90-索引与看板/客户总索引.md
90-索引与看板/customer-index.json
```

用途：

- 让客户库可以快速查询。
- 支持后续分层、跟进、质检。

建议：

每次批量更新客户后运行一次。

### 2.5 生成数据质量报告

功能：检查客户库健康状态。

命令：

```powershell
python scripts/customer_library.py audit --base D:\Claude\客户解决方案库-私有
```

检查内容：

- 活跃客户是否缺下一步动作
- 方案/服务阶段是否缺跟进日期
- 信息完整度是否偏低
- 是否有待处理入口
- 是否有待匹配入口
- 是否有疑似重复客户
- 是否有隐私风险
- 是否有待复核协同任务

生成文件：

```text
90-索引与看板/数据质量报告.md
```

建议：

每周或每月运行一次。

### 2.6 让 Agent 处理客户信息

你可以直接对 Agent 说：

```text
使用 customer-solution-library，客户库路径是 D:\Claude\客户解决方案库-私有。

请处理这条客户信息：
张先生，杭州，李姐转介绍，已婚一孩，想了解重疾险，最近体检发现甲状腺结节，周五晚上有空。
```

你不需要告诉 Agent 内部每一步怎么做。只要说明三件事：

- 使用哪个 Skill。
- 客户库放在哪里。
- 这次要处理什么客户信息。

Agent 会按本仓库规则自动完成价值判断、客户匹配、信息入库、摘要更新、下一步动作和索引刷新。

## 3. 最小计量单位

本系统的最小计量单位不是“客户”，而是“客户信息事件”。

这点很重要。

传统客户管理经常以客户为最小单位：

```text
一个客户 = 一条记录
```

但真实服务中，客户信息是逐步出现的：

- 今天聊了一句需求
- 明天补了一份保单
- 后天发来体检异常
- 下周约了方案沟通
- 一个月后发生理赔咨询

所以本系统的最小计量单位是：

> 一条可被记录、评分、匹配、入库、追踪的客户信息事件。

### 3.1 什么是客户信息事件

客户信息事件可以是：

- 一段聊天记录
- 一段录音转写
- 一次面谈纪要
- 一条客户口述
- 一次保单补充
- 一个健康异常信息
- 一次方案沟通
- 一个跟进动作
- 一次团队反馈

每个事件都应该回答：

| 问题 | 说明 |
|---|---|
| 来源是什么 | 微信、录音、口述、面谈、资料 |
| 时间是什么 | 什么时候发生 |
| 关联谁 | 哪个客户，或待匹配 |
| 有无价值 | S/A/B/C/D 哪一级 |
| 是否需要动作 | 是否要跟进、补资料、出方案 |
| 是否影响判断 | 是否改变客户画像、风险、方案 |

### 3.2 为什么不用客户作为最小单位

因为客户主档案应该保持稳定，不应该把所有聊天细节都塞进去。

正确结构是：

```text
客户主档案 = 当前稳定摘要
客户事件流 = 历史过程
业务模块 = 业务线专属资料
方案与分析 = 阶段性输出
```

这样客户资料越来越多时，系统不会变乱。

### 3.3 一个事件如何进入系统

标准路径：

```text
客户信息事件
→ 入口评分
→ 身份匹配
→ 写入事件流
→ 更新主档案摘要
→ 设置下一步动作
→ 刷新索引
```

如果无法匹配客户，则进入：

```text
00-入口池/02-待匹配/
```

如果价值很低，则进入：

```text
00-入口池/05-低价值归档/
```

## 4. 与传统方案的区别及优势

### 4.1 与 Excel / 表格的区别

传统表格适合记录固定字段，例如：

- 姓名
- 电话
- 来源
- 阶段
- 跟进时间

但表格不擅长保存复杂上下文，例如：

- 客户原话
- 多次沟通变化
- 健康告知细节
- 方案推演过程
- 团队协作记录
- 服务复盘

本系统的优势：

- 用 Markdown 保存长文本和上下文
- 用 YAML 保存结构化字段
- 用索引支持查询和筛选
- 用 Agent 自动摘录、分析和生成方案

### 4.2 与传统 CRM 的区别

传统 CRM 主要管理销售流程：

```text
线索 → 跟进 → 成交 → 回访
```

本系统主要管理客户理解和解决方案：

```text
客户信息 → 价值判断 → 身份匹配 → 客户画像 → 风险分析 → 方案 → 跟进 → 复盘
```

区别：

| 维度 | 传统 CRM | 客户管理库 |
|---|---|---|
| 核心目标 | 管销售流程 | 管客户理解和服务过程 |
| 信息单位 | 客户记录 | 客户信息事件 |
| 信息形式 | 表单字段 | Markdown + YAML + 事件流 |
| AI 适配 | 较弱 | 天然适合 Agent 读取和处理 |
| 客户分析 | 依赖人工 | 可由 Agent 辅助生成 |
| 方案沉淀 | 较弱 | 可形成方案库和复盘库 |
| 同名风险 | 常靠人工识别 | 有身份匹配和防误并档规则 |
| 团队协同 | 常以权限系统为主 | 以任务、摘要、复核、脱敏为主 |

### 4.3 与普通知识库的区别

普通知识库保存知识。

客户管理库保存客户服务过程。

普通知识库关心：

```text
我知道什么？
```

客户管理库关心：

```text
这个客户发生了什么？
我现在如何判断？
下一步应该怎么服务？
```

### 4.4 核心优势

### 优势一：信息不会丢

聊天、录音、口述、资料都可以先进入入口池，不必一开始就整理得很完美。

### 优势二：先判断价值，避免信息垃圾

不是所有信息都值得入库。系统用 100 分制判断信息价值，避免客户库变成杂乱收件箱。

### 优势三：防止同名客户误并档

只有姓名相同不能自动合并，必须结合身份锚点。

### 优势四：适合 Agent 自动处理

Markdown、YAML、事件流、索引文件都适合 Agent 读取、修改、分析和生成输出。

### 优势五：能服务长期客户关系

它不只记录“今天联系了客户”，还记录客户需求变化、方案变化、服务复盘和团队协作。

### 优势六：从个人可用逐步升级到团队可用

一个人可以先用 Markdown 跑起来；客户多了以后，再加入索引、质检、团队协同和权限规则。

## 5. 安装方式

推荐一条指令安装。

### 5.1 Windows：安装到个人 Codex Skills

在 PowerShell 中运行：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.codex\skills" | Out-Null; git clone https://github.com/wytnzs/customer-solution-library.git "$env:USERPROFILE\.codex\skills\customer-solution-library"
```

安装后，对 Agent 说：

```text
使用 $customer-solution-library，帮我初始化客户库。
```

### 5.2 macOS / Linux：安装到个人 Codex Skills

在终端中运行：

```bash
mkdir -p ~/.codex/skills && git clone https://github.com/wytnzs/customer-solution-library.git ~/.codex/skills/customer-solution-library
```

安装后，对 Agent 说：

```text
使用 $customer-solution-library，帮我初始化客户库。
```

### 5.3 安装到某个 Claude Code 项目

如果只想让某个项目使用它，在项目根目录运行：

```powershell
New-Item -ItemType Directory -Force ".claude\skills" | Out-Null; git clone https://github.com/wytnzs/customer-solution-library.git ".claude\skills\customer-solution-library"
```

然后在 Claude Code 中说：

```text
使用 .claude/skills/customer-solution-library 这个 Skill，客户库路径是 D:\Claude\客户解决方案库-私有。
```

### 5.4 仅作为脚本工具使用

如果不安装到 Agent，只想使用脚本：

```powershell
git clone https://github.com/wytnzs/customer-solution-library.git D:\Claude\customer-solution-library
```

进入目录：

```powershell
cd D:\Claude\customer-solution-library
```

测试：

```powershell
python scripts/customer_library.py score-intake --text "张先生说孩子刚上小学，最近体检发现甲状腺结节，想看看重疾险，周五晚上有空。"
```

## 6. 最简开始方式

安装后，让 Agent 执行：

```text
使用 $customer-solution-library。

请在 D:\Claude\客户解决方案库-私有 初始化一个客户库。
以后所有客户信息都先进入入口池，先判断价值，再匹配客户，最后入档。
```

然后你就可以这样使用：

```text
录入客户：张先生，杭州，李姐转介绍，已婚一孩，想了解重疾险，最近体检发现甲状腺结节，周五晚上有空。
```

或者：

```text
整理这段客户聊天记录并入库：……
```

或者：

```text
检查客户库健康状态。
```

---

## 7. 一句话总结

客户管理库的核心不是“存客户”，而是：

> 以客户信息事件为最小单位，让 Agent 帮你判断价值、匹配客户、沉淀档案、生成方案、跟进复盘。
