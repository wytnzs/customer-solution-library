# 与知识库协同使用规则

## 核心原则

客户管理库可以与个人知识库协同，但二者不是同一个库。

推荐采用“三层结构”：

```text
知识库项目
  保存方法论、模板、操作手册、脱敏案例、复盘方法、公开内容

客户管理 Skill
  保存客户管理规则、脚本、字段规范、分析流程

私有客户库
  保存真实客户档案、事件流、方案、跟进记录、产品机会清单
```

## 不能混同的内容

不要把真实客户资料直接写入知识库。

真实客户资料包括：

- 完整姓名
- 手机号
- 身份证号
- 银行卡号
- 完整保单号
- 病历、体检报告原件
- 微信截图原图
- 可识别个人身份的完整沟通记录

## 可以进入知识库的内容

以下内容可以进入知识库：

- 客户管理方法论
- 标准操作流程
- 产品/服务画像模板
- 脱敏案例
- 复盘方法
- 常见问题与话术
- 经过匿名化处理的经验卡片
- 可公开分享的文章、培训材料、团队手册

脱敏案例建议使用：

```text
ANON-0001-体检异常投保案例.md
```

不要使用真实客户姓名作为文件名。

## 推荐项目结构

如果当前项目就是知识库，推荐把 Skill 安装到知识库项目内：

```text
知识库项目/
  .claude/
    skills/
      customer-solution-library/
  客户管理方法论/
  脱敏客户案例/
  产品与服务知识/
```

真实客户库放在单独私有目录：

```text
D:\Claude\客户解决方案库-私有
```

## Agent 操作规则

当用户同时提供知识库路径和客户库路径时：

1. 读取知识库中的方法论、产品知识、话术、脱敏案例作为参考。
2. 读取私有客户库中的客户档案、事件流、方案、跟进记录作为事实来源。
3. 真实客户资料只写回私有客户库。
4. 方法论、模板、脱敏复盘、公开内容才写回知识库。
5. 输出时明确区分“客户事实”“分析推断”“知识库参考”“待确认信息”。

## 推荐启动语

```text
使用项目内 .claude/skills/customer-solution-library。

当前项目是我的知识库，用于保存方法论、模板、产品知识和脱敏案例。
真实客户库路径是：D:\Claude\客户解决方案库-私有。

处理客户信息时：
1. 真实客户资料只写入私有客户库；
2. 可复用方法论、脱敏案例、复盘内容才写入知识库；
3. 生成方案时可以参考知识库中的产品知识和话术；
4. 输出中请区分事实、推断、知识库参考和待确认信息。
```

## 常见错误

错误一：把知识库和客户库并列成两个互不相关的系统。  
正确做法：知识库提供方法论和产品知识，客户库保存真实客户过程。

错误二：把真实客户资料写进知识库。  
正确做法：真实客户资料只进入私有客户库。

错误三：只全局安装 Skill，导致项目中的 Agent 不一定能稳定读取。  
正确做法：优先安装到项目级 `.claude/skills/customer-solution-library`。
