# 产品/服务反向匹配客户规则

## 目标

支持从“产品/服务/经营目标”反向筛选客户，例如：

- 某个保险产品有哪些潜在客户？
- 哪些客户适合知识库搭建服务？
- 哪些客户本周适合做保单整理？
- 哪些客户有转介绍或合作机会？

这类能力是客户库从“资料库”升级为“经营系统”的关键。

## 产品/服务画像

每个产品或服务都应有画像文件，建议放在：

```text
09-产品与机会/products/
```

推荐结构：

```yaml
---
type: product_profile
product_id: PROD-001
product_name: 某产品或服务
business_line: insurance
status: active
suitable_for:
  - 有家庭责任
  - 有保障缺口
not_suitable_for:
  - 明确拒绝长期缴费
matching_signals:
  - 家庭责任
  - 主动咨询重疾险
risk_signals:
  - 健康异常
  - 预算压力
required_information:
  - 已有保单
  - 健康异常详情
---
```

## 匹配逻辑

产品匹配不是简单关键词搜索，应同时考虑：

| 维度 | 说明 |
|---|---|
| 匹配信号 | 客户需求、阶段、标签、事件中出现的正向信号 |
| 风险信号 | 健康、预算、投诉、合规、交付等风险 |
| 不适合信号 | 明确不适合或暂不应推荐的情况 |
| 信息完整度 | 是否足够形成方案或进入沟通 |
| 跟进时机 | 是否有近期动作、预约、资料补充 |
| 客户价值 | 不只看成交概率，也看服务价值和长期关系 |

输出时必须说明：

- 为什么匹配；
- 有哪些风险；
- 还缺什么信息；
- 建议下一步是什么。

## 输出格式

```markdown
# 产品潜在客户清单：<产品>

| 客户 | 匹配度 | 等级 | 匹配原因 | 风险点 | 缺口 | 建议动作 |
|---|---:|---|---|---|---|---|

## 命中客户详情
```

名单表格下方带每个命中客户的详情区：一句话画像、已知需求、匹配原因、风险点、信息缺口、建议动作、档案路径，实现「名单 → 详情」联动。

## 可执行命令

按产品编号筛选：

```powershell
python scripts/customer_library.py product-match --base <客户库路径> --product-id PROD-001
```

按产品画像文件筛选：

```powershell
python scripts/customer_library.py product-match --base <客户库路径> --product-file <产品画像.md>
```

看每个命中客户的完整档案正文节选，加 `--detail`：

```powershell
python scripts/customer_library.py product-match --base <客户库路径> --product-id PROD-001 --detail
```

输出文件：

```text
09-产品与机会/matching/<产品编号>-潜在客户清单.md
09-产品与机会/matching/<产品编号>-潜在客户详情.md   （--detail 时额外生成）
```

## 使用原则

1. 产品画像越清晰，筛选越有价值。
2. 高匹配不等于可以直接推荐，仍要看信息缺口和风险信号。
3. 涉及保险、健康、理赔、法律、财务承诺时必须人工复核。
4. 输出默认是内部经营清单，不是客户可读内容。
5. 如果产品画像缺失，应先创建产品画像，再筛选客户。
6. 如果缺少 `required_information`，不应给出“高匹配”结论，应优先提示补齐缺口。
7. 如果存在多个风险信号，应降级为“需人工复核/待补资料”。
8. 如果出现 `not_suitable_for` 信号，即使有匹配信号，也应谨慎处理。
