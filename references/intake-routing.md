# 信息入口路由与信号价值评分

## 目标

入口优化的目标不是“把所有信息都整理好”，而是快速判断一段信息是否值得投入整理成本，并决定它应该去哪里。

入口处理必须回答四个问题：

1. 这段信息是否有客户价值？
2. 是否能匹配到具体客户或客户群？
3. 是否会影响判断、方案、跟进或风险？
4. 应该立即入档、待匹配、待确认、低价值归档，还是丢弃？

## 入口 YAML

```yaml
---
type: customer_intake
intake_id: INTAKE-20260711-001
source_type: audio_transcript
captured_at: 2026-07-11
captured_by: self
related_name:
possible_customer_ids: []
match_status: unmatched
business_line: []
privacy_level: high
signal_score: 0
signal_level: unscored
route: pending_review
action_required: false
status: pending
---
```

## 100 分信号评分制

总分 100 分。默认按以下五类评分。

| 维度 | 分值 | 判断问题 |
|---|---:|---|
| A. 身份识别价值 | 15 | 是否帮助识别客户是谁、来自哪里、与谁相关？ |
| B. 业务相关价值 | 20 | 是否涉及保险、咨询、合作、服务、转介绍等业务线？ |
| C. 决策/行动价值 | 25 | 是否会触发下一步动作、预约、补资料、方案调整？ |
| D. 风险/责任价值 | 25 | 是否涉及健康、理赔、投诉、承诺、期限、合规、财务责任？ |
| E. 长期资产价值 | 15 | 是否能沉淀为客户画像、常见异议、方法论、团队经验？ |

## 评分细则

### A. 身份识别价值，15 分

| 得分 | 标准 |
|---:|---|
| 0 | 完全没有身份线索 |
| 3 | 只有模糊称呼，如“一个客户”“张先生” |
| 6 | 有姓名/昵称/来源中的一项 |
| 10 | 有姓名/昵称 + 一个辅助锚点，如城市、来源人、职业 |
| 15 | 有客户编号、脱敏联系方式，或足以高置信匹配的多重锚点 |

### B. 业务相关价值，20 分

| 得分 | 标准 |
|---:|---|
| 0 | 与客户服务或业务无关 |
| 5 | 泛泛互动，暂不影响业务 |
| 10 | 提到初步兴趣、一般问题、模糊需求 |
| 15 | 涉及明确业务线，如保险、咨询、合作、转介绍 |
| 20 | 涉及关键业务资料，如保单、健康告知、预算、项目目标、决策人 |

### C. 决策/行动价值，25 分

| 得分 | 标准 |
|---:|---|
| 0 | 不需要任何动作 |
| 5 | 可作为背景了解 |
| 10 | 需要轻微跟进，如发资料、简单回复 |
| 15 | 需要安排明确下一步，如约时间、补资料、建档 |
| 20 | 会影响方案、报价、保障分析、协同任务 |
| 25 | 有明确期限、客户承诺、待办责任或必须马上处理 |

### D. 风险/责任价值，25 分

| 得分 | 标准 |
|---:|---|
| 0 | 无明显风险 |
| 5 | 轻微误解或普通顾虑 |
| 10 | 涉及预算压力、家庭责任、职业风险、决策阻力 |
| 15 | 涉及健康异常、既往症、保单责任、理赔可能性 |
| 20 | 涉及投诉、拒赔、误导风险、承诺、期限、缴费、重要材料 |
| 25 | 涉及重大合规/法律/财务/隐私风险，必须保留证据链 |

### E. 长期资产价值，15 分

| 得分 | 标准 |
|---:|---|
| 0 | 无复用价值 |
| 3 | 仅对当前对话有用 |
| 6 | 可补充客户画像 |
| 10 | 可沉淀为常见问题、异议、话术或服务经验 |
| 15 | 可反哺知识卡片、团队培训、产品化流程或脱敏案例 |

## 信号等级与路由

| 总分 | 等级 | 默认路由 | 动作 |
|---:|---|---|---|
| 75-100 | `S` | 立即处理 | 建沟通记录，匹配客户，必要时更新主档案/方案/跟进 |
| 55-74 | `A` | 待处理 | 摘要入事件流，视情况更新主档案 |
| 35-54 | `B` | 轻记录 | 保留短摘要，进入低频跟进或待确认 |
| 15-34 | `C` | 低价值归档 | 不更新主档案，短期保留 |
| 0-14 | `D` | 可丢弃 | 除非涉及隐私/合规，不投入整理 |

## 硬触发规则

出现以下任一情况，即使总分不高，也至少按 `A` 级处理：

- 客户明确提出下一步动作、预约、补资料、回访时间。
- 涉及健康异常、既往症、体检报告、病历、核保。
- 涉及理赔、拒赔、投诉、纠纷、误导销售。
- 涉及保单号、缴费、续保、退保、保全。
- 涉及客户明确承诺、你方承诺、团队成员承诺。
- 涉及身份证、银行卡、手机号、病历等敏感信息。
- 涉及转介绍、关键合作机会、决策人变化。
- 涉及客户强烈情绪：愤怒、焦虑、不信任、强烈购买意愿。

出现以下任一情况，即使有业务关键词，也不得直接入主档案：

- 身份无法确认。
- 信息明显是转述且来源不清。
- 与旧档案关键事实冲突。
- 只有姓名相同，没有其他身份锚点。

## 扣分项

| 情况 | 扣分 |
|---|---:|
| 与已有记录高度重复 | -10 |
| 时间过久且无后续价值 | -10 |
| 内容只有寒暄 | -15 |
| 身份无法确认且无业务价值 | -20 |
| 明显与业务无关 | -30 |

扣分后最低为 0 分。

## 可执行判断公式

```text
signal_score = A + B + C + D + E - penalty
```

然后按硬触发规则修正等级。

## 示例

### 示例 1：高价值

“张先生说孩子刚上小学，最近体检发现甲状腺结节，想先看看重疾险，周五晚上有空。”

评分：

- 身份识别：10
- 业务相关：20
- 决策/行动：25
- 风险/责任：15
- 长期资产：10
- 总分：80，S 级

路由：立即建沟通记录，匹配客户，更新保险业务模块，设置周五跟进。

### 示例 2：中价值

“李姐介绍了一个朋友，说可能想了解保险，但还没具体聊。”

评分：

- 身份识别：6
- 业务相关：10
- 决策/行动：10
- 风险/责任：0
- 长期资产：3
- 总分：29，但因转介绍硬触发，升为 A 级

路由：建线索，待补身份锚点。

### 示例 3：低价值

“王总朋友圈点了个赞。”

评分：

- 身份识别：3
- 业务相关：0
- 决策/行动：0
- 风险/责任：0
- 长期资产：0
- 总分：3，D 级

路由：不入档。若持续多次互动，可累计为内容触达信号。

## 团队执行口径

团队成员不需要写长分析，只需在入口卡里填：

```yaml
signal_score: 68
signal_level: A
route: pending_process
score_reason: 有明确保险需求和下一步补资料，但身份锚点不足
```

如无法评分，先标记：

```yaml
signal_level: unscored
route: pending_review
```

## 批量处理入口池

入口池积压时，用同一套评分一次性处理全部待处理/待匹配/待确认入口：

```powershell
python scripts/customer_library.py intake-pool --base "<你的私有客户库路径>"
python scripts/customer_library.py intake-pool --base "<你的私有客户库路径>" --json
```

输出 `90-索引与看板/入口评分汇总.md`，按分数从高到低排列，便于先处理最值得经营的入口。
