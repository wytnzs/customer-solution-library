# 团队协同与分享规则 v2.1

## 原则

客户协同遵守“最小必要信息”原则：谁处理什么任务，就只给他完成任务所需的信息。

不要把完整客户档案随意转发到群聊或共享文档。

## 分享类型

| 类型 | 用途 | 内容 |
|---|---|---|
| 完整内部档案 | 直接负责人深度服务 | 客户主档案、事件流、业务模块 |
| 协同摘要 | 团队成员处理单一任务 | 背景、任务、注意事项、输出要求 |
| 脱敏案例 | 培训、复盘、内容生产 | 去身份化事实、过程、经验 |
| 客户可读版 | 发给客户 | 稳妥表达，不含内部判断 |

## 协同任务 YAML


## 任务状态

| status | 含义 |
|---|---|
| `pending` | 待处理 |
| `in_progress` | 处理中 |
| `needs_review` | 待复核 |
| `done` | 已完成 |
| `blocked` | 被阻塞 |
| `cancelled` | 已取消 |

## 权限层级

| 层级 | 内容 | 处理 |
|---|---|---|
| P0 | 公开方法论、脱敏案例 | 可进入知识库 |
| P1 | 客户摘要、非敏感背景 | 可团队共享 |
| P2 | 详细沟通记录、方案判断 | 仅任务相关成员 |
| P3 | 健康、保单、理赔、财务、联系方式 | 严格限制 |
| P4 | 身份证、病历原件、银行卡等 | 不建议 Markdown 明文保存 |

## 协同摘要模板

```markdown

## 客户编号

## 当前状态

## 需要协助的问题

## 可查看资料

## 不可外传信息

## 输出要求

## 截止时间
```

## 交接完成标准

协同任务不能只停留在任务卡里。完成时必须检查：

1. 是否产生明确输出。
2. 输出文件路径是否写入 `output_path`。
3. 是否需要复核；如需要，是否进入 `needs_review`。
4. 复核完成后，是否回写客户主档案或业务模块。
5. 是否更新客户的 `next_action` 和 `next_followup_date`。
6. 是否记录处理人、完成时间和关键判断。

完成记录模板：

```markdown
## 完成记录

- 处理人：
- 完成时间：
- 输出路径：
- 是否复核：
- 复核人：
- 是否已回写客户档案：
- 下一步动作：
```

## 复核要求

以下任务必须复核：

- 保险方案结论
- 健康/核保判断
- 理赔/拒赔判断
- 投诉/纠纷回复
- 对客户的正式书面建议
- 涉及敏感信息的外发内容
