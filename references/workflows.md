# 客户解决方案库工作流

## 1. 新客户录入

流程：

1. 搜索是否已有客户。
2. 若无，创建 `customer_id`。
3. 创建主档案。
4. 把原始信息保留在沟通记录或收件箱。
5. 提取已知事实、待确认信息、初步需求。
6. 设置 `customer_type`、`business_line`、`info_completeness`。
7. 写入 `next_action`。
8. 刷新索引。

不要因为信息不全而拒绝建档。客户库必须允许从 L0 开始。

## 2. 分批补全

每次获得新信息，按“三步更新”：

1. 先写原始记录：`02-沟通记录/<customer_id>/YYYY-MM-DD-主题.md`
2. 再更新主档案摘要：补字段、改完整度、改下一步动作。
3. 如果影响判断，再更新需求分析或专属方案。

变更记录格式：

```markdown
## 变更记录

- 2026-07-11：补充客户已有重疾险信息；完整度 L2 → L3；下一步改为核对医疗险责任。
```

## 3. 查询客户

流程：

1. 用 `customer_id` 精确找。
2. 用别名、标签、来源、业务线、正文关键词搜索。
3. 如果多项命中，输出候选项：

```markdown
找到 3 个可能客户：

1. CUST-0001｜杭州三口之家｜insurance｜最近更新 2026-07-11
2. CUST-0014｜张先生-企业主｜insurance, partnership｜最近更新 2026-07-09
3. ORG-0003｜某培训机构｜knowledge_service｜最近更新 2026-07-06

请确认要查看哪一个。
```

4. 读取主档案和最近记录。
5. 按用户需要输出速览、分析、方案或跟进建议。

## 4. 客户分析

分析时严格分三层：

| 层级 | 内容 |
|---|---|
| 事实 | 客户明确提供或文件记录的信息 |
| 推断 | 根据事实形成的初步判断，必须说明依据 |
| 待确认 | 决策前必须补充的信息 |

保险客户分析维度：

- 家庭责任
- 收入与负债
- 已有保障
- 健康/核保关注点
- 预算承受能力
- 风险优先级
- 沟通顾虑

非保险客户分析维度：

- 客户目标
- 当前卡点
- 决策链条
- 预算/时间/资源约束
- 可交付成果
- 合作机会
- 下一步推进动作

混合客户先输出综合画像，再分业务线分析。

## 5. 专属方案生成

默认输出内部版，不直接承诺结果。

方案结构：

1. 当前客户画像
2. 核心问题
3. 风险/机会排序
4. 解决顺序
5. 建议动作
6. 暂不建议动作
7. 需要补充的信息
8. 沟通建议
9. 下一步跟进

保险相关边界：

- 不承诺一定承保。
- 不承诺一定赔付。
- 不替代条款、核保、理赔、法律意见。
- 涉及疾病、体检异常、既往症时，提示需结合健康告知、病历、检查报告人工复核。

## 6. 跟进管理

每个客户主档案必须尽量有：

```yaml
next_action:
next_followup_date:
```

跟进记录写入：

```text
06-服务跟进/YYYY-MM-DD-本周客户跟进.md
```

跟进清单格式：

```markdown
| 日期 | customer_id | 客户 | 动作 | 原因 | 优先级 | 状态 |
```

## 7. 客户分层

默认分层：

| 层级 | 定义 | 策略 |
|---|---|---|
| A | 高信任、高需求、高服务价值 | 深度分析、定期复盘 |
| B | 有需求但资料/信任/预算待补 | 教育和轻方案推进 |
| C | 潜在需求或内容触达对象 | 轻触达、内容培育 |
| D | 低匹配或暂无行动可能 | 保持基础记录 |

不要只按成交可能性分层。应同时考虑服务价值、长期关系、需求紧迫度和资源投入。

## 8. 复盘

复盘触发：

- 成交
- 未成交
- 客户迟疑
- 理赔/拒赔
- 方案调整
- 重大沟通
- 客户转介绍

复盘结构：

```markdown
# 客户服务复盘

## 背景

## 发生了什么

## 有效动作

## 无效动作

## 客户真实顾虑

## 可沉淀的方法

## 可反哺的知识卡片/选题

## 下次改进
```
