# 客户管理库结构骨架

客户管理库（Obsidian vault）的目录结构模板。**本目录不含任何客户数据**——所有业务目录只放 `.gitkeep` 占位。

## 数据边界（重要）

| 目录 | 职责 | 是否可入库 |
|---|---|---|
| `00-入口池/` | 待处理/待匹配/待确认的客户线索 | ❌ 内容是私有客户线索 |
| `01-客户档案/` | 客户档案（`CUST-XXXX.md`） | ❌ 核心客户数据 |
| `02-客户事件流/` | 客户事件记录 | ❌ |
| `03-业务模块/` | 保险/咨询/内容等业务资料 | ❌ 常含客户关联信息 |
| `04-方案与分析/` | 客户方案、分析 | ❌ |
| `05-团队协同/` | 协同任务、脱敏案例 | ❌（`06-脱敏案例` 脱敏后可另存） |
| `06-服务跟进/` | 跟进记录 | ❌ |
| `07-客户分层/` | 客户分层判断 | ❌ |
| `08-复盘案例/` | 复盘 | ❌ 常含客户信息 |
| `09-产品与机会/` | 产品画像、匹配结果 | ⚠️ `products/` 产品定义可入库，`matching/` 匹配结果含客户 ❌ |
| `10-客户洞察/` | 客户洞察 | ❌ |
| `90-索引与看板/` | 索引、看板、报告 | ⚠️ 全部由脚本生成，客户名会出现在其中 → ❌ |
| `99-模板与规则/` | 模板、规则 | ✅ **唯一可入库** |

**一句话：除 `99-模板与规则/` 外，其余目录内容均为私有客户数据，禁止纳入版本控制。** 结构本身（空目录 + `.gitkeep`）可以入库，供骨架复用。

## 使用方法

方式一：复制本目录到本地作为 Obsidian vault 打开：

```bash
cp -r templates/customer-vault/ <你的客户库路径>
```

方式二：用脚本命令生成全新骨架（推荐，保证与最新结构一致）：

```powershell
python scripts/customer_library.py init --base "<你的私有客户库路径>"
```

## 模板

- `99-模板与规则/客户档案模板.md` — 客户档案模板（含画像字段：年龄/收入/职业/城市/家庭结构）
- `99-模板与规则/产品服务画像模板.md` — 产品/服务画像模板

## 常见问题

- **本地库模板是旧版？** `init` 只在文件不存在时写入，已存在的旧模板不会自动更新。把新版模板复制覆盖 `99-模板与规则/客户档案模板.md` 即可（历史档案不受影响，新档案用新版）。
- **这些目录的用途？** 见 `docs/客户管理库操作手册.md` 的数据模型章节。
